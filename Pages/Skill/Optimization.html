PERFORMANCE

OPTIMIZATION

CPU、GPU、VRAM、読み込みを、勘ではなく自作の計測ツールの数字をもとに改善します。

01

OVERVIEW

概要

VECTOR REIGN で行った、CPU、GPU、VRAM、読み込みの改善です。計測ツールを自作し、実際に遊んだときの記録から問題を探せるようにしました。

02

ARCHITECTURE

計測の仕組み

  • プロファイラー : エディターで、全体、スコープ、GPU、ECS、スレッド、パーティクル、VRAM を確認できます。
  • HitchMonitor : 60FPS を割ったフレームの中身(処理時間、PSO 生成、同期読み込みなど)をファイルへ書き出します。
  • VRAM の集計 : リソースに用途の札を付け、消えたときに自動で引きます。

03

IMPLEMENTATION

実装

CPU : 爆風のたびにカクつく

  • 原因 : 判定で機体の判定メッシュの三角形を全件集めていて、機体のそばの爆発が1回 27 ms かかっていました。
  • 修正 : 広域判定でボディを集めてから、ボディごとに最初の当たりで打ち切る形にしました。

CPU : 敵の初出現で止まる

  • 原因 : エフェクトのパーティクル用 GPU プールを初出現のときに作っていて、26〜30 ms 止まっていました。
  • 修正 : 先読みで届いた時点で、ロード中にプールを作るようにしました。

CPU : 大量の問い合わせを減らす

  • 判定対象がない問い合わせは Jolt Physics へ行かずに返し、ボイドの大量の問い合わせを省いています。
  • ECS のクエリはアーキタイプごとにキャッシュし、新しいアーキタイプだけを照合します。
  • 最大 4,000 体のボイドは小隊に分け、近傍探索の範囲を絞っています。

GPU : 描かないものと、計算しないものを決める

  • 増幅シェーダーで、メッシュレット単位の視錐台カリングと法線コーンカリングを行います。
  • LOD は画面に占める割合から GPU で選びます。影はカスケードごとに違う段を選べます。
  • GI は低解像度で計算し、時間・空間デノイズの後にアップスケールします。
  • 可視判定だけのボリューム影は、インラインレイトレ(RayQuery)で軽く処理します。
  • 戦闘シーンのパイプラインは GI と反射を外しています。ボイドは光の筋が点いている間だけレイトレのワールドへ登録します。

VRAM : 使う分だけ確保する

  • 原因 : 使わない領域まで固定で確保していました。用途別の集計を作り、数字を見ながら削減しました。
  • 可変長のメガバッファ : 予約リソースで、必要な分だけ 4 MB 単位でヒープを割り当てます。空きが続いた領域は、GPU が使い終わったのをフェンスで確かめてから手放します。
  • 頂点形式の分割 : 静的頂点は八面体エンコードで 32 バイト、ボーン割り当ては 16 バイトの別バッファ、アニメーション後は 20 バイトに分けました。
  • メモリエイリアシング : 生存区間が重ならないリソースを、1つのヒープ内で共有します。
  • BLAS 圧縮 : 静的 BLAS はビルド後に圧縮サイズを読み戻し、複数フレームに分けて差し替えます。

読み込み : ゲームを止めない

  • GPU への転送はコピーキューとコンピュートキューへまとめて流し、完了をフェンスで見張ります。モデル1体で数百回の submit になるのを防ぐバッチの仕組みも持っています。
  • シーンはロード画面の裏で先読みと組み立てを行い、落ち着くのを待ってから切り替えます。
